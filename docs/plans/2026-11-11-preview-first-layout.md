# 修改規劃：選取框只留框線＋手指縮放；預覽固定夠大、其他功能往下滑

- 來源：使用者 2026-11-11 看完第 2 次修正（四角小點、時間軸精簡、預覽約 40%）後的回饋。
- 使用者原話：
  1. 「選取框一率不需要小圓點，只需要有框框可以選取字串並用手指控制縮放就行」
  2. 「預覽不要太小，如果需要其他功能，可以往下滑新增相關功能，不要擠到預覽畫面」
- 使用者對第一版規劃的更正（2026-11-11）：「第一點可以，第二點我的意思是頁面可以整體往下滑新增功能，但往上滑可以看到不會縮小的預覽畫面」→ **整頁一起捲動**：預覽**不是**固定在螢幕上，往下滑時預覽會跟著捲上去（看不到），往上滑回來就看到原尺寸的預覽；預覽大小永遠不變。§2-① 已照這個改寫。
- 狀態：**①②③ 已實作並通過 e2e（2026-11-11）**；iPhone 真機待驗證（PLAN §7）。截圖 `docs/screenshots/preview-first/`。
- 會**取代**前一份規劃 `2026-11-11-iphone-feedback-2.md` §②裡的這幾項：四角小點、旋轉點、時間軸精簡模式、面板 25dvh 上限（那些程式都要拿掉或改掉）。保留：選取框貼著看得到的內容（`selectionBox`）、很小的物件點選範圍至少 40px、空專案匯入鈕在預覽中央、全螢幕預覽鈕。
- 順序：**① 版面（整頁往下捲，預覽大小不變）→ ② 選取框只留框線＋雙指縮放旋轉 → ③ 面板裡補「大小／旋轉」滑桿（不用手勢也能調）→ 測試、截圖、紀錄**。①② 各自 commit。

## 1. 現況（已查證程式）

| 項目 | 現在的做法 | 問題 |
|---|---|---|
| 版面 | `.editor` 是 `height:100dvh` 的直向 flex：頂列＋預覽（`flex:1`）＋播放列＋時間軸＋分頁＋面板。面板展開時時間軸縮成一條、面板最高 25dvh，預覽拿剩下的。 | 預覽會被下面的東西「擠小」；iPhone 13 尺寸只剩約 40%，真機（有 Safari 網址列）更小。 |
| 時間軸 | 自己有一個垂直捲動區（`viewH` 最高 140px，多條軌道要在裡面上下捲）。 | 改成整頁可往下捲後，時間軸裡再捲一次會和外層捲動打架。 |
| 選取框 | `Preview.tsx`：框線＋四個角點（`data-testid="scale-handle"`）＋旋轉點（`rotate-handle`）；雙指縮放旋轉已經有（兩個 pointer 時 `gesture.type='pinch'`）。 | 使用者不要任何圓點。 |
| 雙指 | 只有在**已經選取**物件時，第二根手指落下才開始縮放；兩根手指都要落在舞台內。 | 物件很小時兩指很難都放在框裡——現在的程式其實不要求落在框裡（只要在舞台內），這點要保留並測試。 |

## 2. 要改的事

### ① 版面：整頁往下滑看其他功能，往上滑回來是不會縮小的預覽

1. **編輯器變成一般可捲動的頁面**（`src/app/pages/Editor.tsx`、`src/app/styles.css`）：由上到下依序是 頂列 → 預覽 → 播放列 → 時間軸 → 分頁列（剪輯／疊加／文字／圖層）→ 目前分頁的面板內容。整頁一起上下捲（`.editor` 不再是 `height:100dvh` 的 flex，改成 `min-height:100svh` 的一般區塊，捲動交給頁面本身或 `.editor { overflow-y:auto; height:100svh }` 二擇一——**建議用頁面本身捲動**，iOS 的回彈與網址列收合比較自然）。
   - 往下滑：預覽跟著捲上去（看不到），露出時間軸、分頁、各項設定。
   - 往上滑回頂端：預覽是原本的大小，**任何情況都不縮小**。
2. **預覽大小固定**：
   - 寬度撐滿螢幕（左右不留黑邊，橫式專案也一樣），高度依專案比例算；但**最高不超過「一個螢幕高 − 頂列 − 播放列」**（`calc(100svh - 52px - 48px)`），讓捲到最上面時整個預覽和播放鈕都看得到。9:16 在 iPhone 13 約 564pt 高（約 85% 螢幕），寬度跟著縮成約 317pt。
   - 用 `svh` 不用 `dvh`：Safari 網址列伸縮時 `dvh` 會變，預覽會抖。
   - 拿掉所有「面板展開→預覽變小」的邏輯：`compactTimeline`（`uiStore`、`Toolbar.tsx` 的 effect、`Timeline.tsx` 的 `compact`）、`.panel.tall { max-height }`、`.panel { max-height: 26dvh }`、`.panel.scroll`、`.stage-wrap { flex:1 }`。面板內容多就讓頁面變長。
3. **頂列黏在最上面**（`position: sticky; top: 0`，44–52px）：捲到下面調設定時，「復原／重做」「返回」仍按得到。**分頁列**也黏住（`top: 頂列高度`），捲到面板深處時切分頁不用捲回去；字卡面板的子分頁列（文字／版面／字塊／描邊陰影／裝飾／＋新增）黏在分頁列下面。播放列**不黏**（跟著預覽捲走）。
4. **在預覽上滑手指也要能捲頁面**（重要：預覽佔了快一整個螢幕，如果預覽整塊都吃掉觸控，使用者會滑不下去）：
   - 舞台背景改成 `touch-action: pan-y`（上下滑＝捲頁面）。
   - 每個可以拖的物件（疊加影片、照片、文字、圖形；主軌除外）在舞台上放一個**看不見的觸控區**（DOM 元素，位置／大小／旋轉跟 `selectionBox` 一樣，最小 44px），`touch-action: none`：手指按在物件上＝拖物件，按在空白處上下滑＝捲頁面。
   - 選取中的物件，觸控區外擴 24px，雙指比較好放。
   - 主軌片段被（從時間軸）選取時，它的觸控區是整個舞台 → 這時預覽上不能捲頁面；點時間軸空白處或預覽外取消選取即可。在日誌寫明。
   - 單點空白處＝取消選取（現在的行為保留）。
5. **時間軸不再自己上下捲**：高度＝全部軌道的內容高度，水平仍可滑動（`touch-action: pan-x pan-y`），垂直交給頁面。「選到的軌道自動捲進可視範圍」改成 `scrollIntoView({ block: 'nearest' })`。
6. 切換分頁時，如果分頁列已經捲到頂端以上，保持在分頁列的位置（不要跳回頁首、也不要停在面板一半）。
7. **全螢幕預覽鈕保留**：按下時隱藏下面所有東西、預覽撐滿螢幕。
8. `Sheet`（底部彈出面板）、toast、匯入中遮罩用 `position: fixed`，不受頁面捲動影響（確認）。
9. iPhone 注意（列入 `docs/PLAN.md §7`）：在預覽空白處上下滑能捲頁面、按在物件上能拖物件、滑桿水平拖曳不會變成捲頁面、時間軸水平滑動不會變成捲頁面。

### ② 選取框：只有框線，用手指縮放

1. **拿掉四角小點與旋轉點**（`Preview.tsx` 的 `handles`、`onHandleDown`、`.sel-dot` 樣式、`data-testid="scale-handle"`/`rotate-handle`）。選取框只剩一個細框（1.5px 白＋1px 黑外圈，物件旋轉時框跟著轉）。
2. **手勢**（沿用現有程式，補強）：
   - 單指點物件＝選取；單指拖＝移動（吸附、安全區參考線照舊）。
   - **雙指＝縮放＋旋轉**：第一根手指放在物件（或選取中物件外擴 24px 的觸控區）上、第二根手指放在預覽任何地方，就縮放旋轉這個物件（舞台空白處是 `pan-y`，兩指都放在空白處時瀏覽器可能把它當捲動，iOS 真機要驗證；不行的話改成：有選取物件時，舞台背景也換成 `touch-action:none`，單指上下滑仍用程式自己捲頁面）。
   - 雙指時也顯示安全區參考線（現在已有 `setDragging(true)`）、旋轉吸附 0/90/180/270（目前雙指沒有吸附 → 改成用 `snapRotation`）。
   - 一次雙指手勢＝一步復原（`setTransform` 加 coalesce key `pinch:<id>`；現在雙指沒有 coalesce，會產生很多步）。
   - iOS Safari：在舞台上 `gesturestart`/`gesturechange` 呼叫 `preventDefault()`，避免雙指變成整頁縮放（`touch-action:none` 之外的保險）。
3. 主軌從時間軸選取時，預覽上也只有細框（滿版），雙指可放大裁切（現在的行為保留）。

### ③ 面板裡的「大小／旋轉」（不用手勢也能精準調，也給測試用）

- 在**圖層**分頁的屬性區（`LayersTab`，對所有選取的物件）最上面加：「大小」滑桿（5%–400%，對應 `transform.scale`）、「旋轉」滑桿（−180°～180°，步進 1°）、「置中」按鈕（x=0.5, y=0.5）、「轉正」按鈕（rotation=0）。文字面板「版面」子分頁也放同樣的「大小」「旋轉」（同一個元件）。
- 拖滑桿 coalesce 成一步復原。

## 3. 會動到的檔案

- `src/app/editor/Toolbar.tsx`（拿掉 compact effect；`LayersTab` 加大小/旋轉/置中/轉正）、`src/app/editor/TextPanel.tsx`（版面加大小/旋轉；子分頁 sticky 位置）
- `src/store/uiStore.ts`（拿掉 `compactTimeline`）
- 測試：
  - 新 `e2e/helpers.ts` 的 `pinch(page, {cx, cy, from, to, angle})`：用 CDP `Input.dispatchTouchEvent` 送兩點觸控（Chromium 會轉成 pointer 事件），供所有需要縮放旋轉的測試用。
  - 要改的既有測試：`phase2.spec.ts`「預覽上的選取框…」（角點/旋轉點 → 雙指）、`fix-safe-zone.spec.ts`（`scale-handle` 數量 → 改驗沒有圓點）、`fix-preview-size.spec.ts`（精簡時間軸、角點、40% → 改成新版面的檢查）、`phase2.spec.ts`「底部分頁：點目前的分頁會收合面板，預覽畫面變大」→ 改成「收合面板，**預覽大小不變**」。**改測試，不要刪測試**。

## 4. 驗收（截圖放 `docs/screenshots/preview-first/`）

- [ ] iPhone 13 尺寸（390×664）：捲到最上面時，9:16 預覽高度 ≥ **80%**（扣掉頂列和播放列後撐滿），整個預覽和播放鈕都在畫面內；在剪輯／疊加／文字／圖層每個分頁、面板展開或收合、選取文字前後，**預覽的寬高都一樣**（e2e 量 `stage` 的寬高，誤差 ≤ 1px）。
- [ ] 整頁可以往下捲：往下捲之後看得到時間軸、分頁、面板，捲到最下面點得到最後一個控制項（例如裝飾的最後一個滑桿）；頂列（復原／重做）與分頁列捲動時一直看得到；捲回頂端預覽完整出現。
- [ ] 在預覽空白處用觸控往上滑（CDP 單點觸控拖曳）→ 頁面往下捲；按在文字上拖 → 文字移動、頁面不捲。
- [ ] 多條軌道時，時間軸全部列都顯示（沒有內部垂直捲動），往下捲就看得到。
- [ ] 選取框沒有任何圓點（`.sel-dot` 數量 0），只有框線。
- [ ] 雙指（CDP 兩點觸控）：選取中的文字可放大縮小、旋轉（吸附到 90°），一次手勢＝一步復原；兩指在框外也有效；沒選取時雙指會選到中點下的物件。
- [ ] 圖層分頁／版面子分頁的「大小」「旋轉」「置中」「轉正」可用。
- [ ] 全螢幕預覽仍可用。
- [ ] `npm run check`、`npm run e2e -- --trace off` 全過（整套連跑 2 次）。
- 🔴 真機（列入 `docs/PLAN.md §7`）：雙指縮放不會變成整頁縮放；下區捲動和滑桿、時間軸水平滑動不打架；Safari 網址列伸縮時預覽不抖。

## 5. 回覆使用者時要說的（白話）

- 整頁可以往下滑看時間軸和各項設定；往上滑回最上面就是大大的預覽（大約佔螢幕八成多），不管打開什麼設定都不會變小。頂端的復原／重做和分頁列會一直停在上面。
- 在預覽空白處上下滑可以捲頁面；按在文字或圖形上拖就是移動它。
- 選取文字只會有一個框，沒有任何圓點；兩根手指放在畫面上就能放大縮小、旋轉。想精準調也可以用「圖層」裡的「大小」「旋轉」滑桿。
