## A. 播放順暢＋影片聲音

### A-1 卡頓的原因（已查證程式）

| 原因 | 位置 | 說明 |
|---|---|---|
| 每一格都整個編輯器重新畫 | `src/app/pages/Editor.tsx`：`player.subscribe((t,p) => { setTime(t); … })` | 播放時每秒 60 次 `setTime` → `EditorBody` 整個重畫（時間軸、分頁、面板、字卡面板全部）。手機上很吃 CPU。 |
| 每一格把影片畫到暫存畫布再上傳 | `src/engine/compositor.ts`（`frameCanvas` → `CanvasSource`） | 每個影片圖層每一格都要 `drawImage` 到一張畫布（最大 2 倍預覽大小），再整張上傳到 GPU。iPhone 拍的 4K HEVC 每格都這樣做，是主要瓶頸。 |
| 時間軸每格跟著捲 | `Timeline.tsx` `syncScroll` | 每格改 `scrollLeft`，會觸發排版。 |
| 播放中重新對時跳格 | `player.ts` `DRIFT = 0.3`、`el.currentTime = s` | 影片和時鐘差 0.3 秒就硬跳，畫面會頓一下。 |

### A-2 改法

1. **時間顯示獨立成小元件**：`<TimeText />` 自己訂閱 player，最多每 100ms 更新一次；`EditorBody` 不再持有 `time` state（播放／暫停鈕用 `playing` 即可，只在狀態改變時更新）。時間軸捲動用 ref 直接改 `scrollLeft`，不經過 React。
2. **影片直接當 GPU 貼圖**：沒有裁切、沒有特殊處理的影片圖層改用 Pixi 的 `VideoSource`（`Texture.from(videoElement)` 並關掉它的自動播放），每格只 `source.update()`，不再經過暫存畫布；裁切改用貼圖的 `frame`（子矩形），圓角照舊用遮罩。照片維持現狀。
3. **只在需要時重畫**：有 `requestVideoFrameCallback` 的瀏覽器（Safari 15.4+ 有）用它驅動重畫；沒有新影格就不重畫。
4. **播放中預覽解析度降一點**：播放中長邊 720、暫停時 960（`previewSize`）。
5. **對時改柔性**：差距小（< 0.3 秒）時用 `playbackRate` 微調追上，只有差很多才跳 `currentTime`。
6. 除錯用：`vc-debug=1` 時預覽角落顯示 FPS 和每格耗時（給 e2e 和真機回報用）。

### A-3 沒有聲音的原因（已查證程式，需真機確認）

- `src/engine/mediaPool.ts` 的 `unlock()`：在使用者按播放時，對每個 `<video>` **以靜音** `play()` 再在 promise 回來時 `pause()`。問題：
  1. iOS 的「使用者點擊才可以出聲播放」只對**當下那一次、不靜音的** `play()` 有效；靜音解鎖不代表之後可以出聲。
  2. promise 回來的 `pause()` 可能把**剛開始出聲播放的主軌影片又停掉**，之後在 `requestAnimationFrame` 裡再 `play()` 已經不算使用者點擊 → iOS 拒絕出聲（程式把錯誤吞掉了，`.catch(() => {})`）。
- 另外要排除：`asset.hasAudio` 判斷錯。
- **使用者已確認（2026-11-12）**：測試時有打開影片聲音，仍然沒聲音。使用者要的是**影片聲音**，不是手機的通知鈴聲；手機在靜音模式（鈴聲關掉）時，影片也要有聲音（像 YouTube、IG 那樣）。

### A-4 改法

**規定：影片聲音不受 iPhone 靜音開關影響。** iOS 的規則（實作時要在真機確認）：
- `<video>`／`<audio>` 元素的聲音屬於「播放媒體」，靜音模式下照樣有聲音。
- 但 Web Audio（`AudioContext`）預設屬於「環境音」，**靜音模式下會沒聲音**。要用 Web Audio，必須先設 `navigator.audioSession.type = 'playback'`（Safari 16.4 以後才有的 Audio Session API，版本以真機為準）。
- iOS 上 `<video>.volume` 是設不了的（永遠 100%），所以現在的「音量」滑桿在 iPhone 上本來就沒作用；要能調音量，聲音必須經過 Web Audio 的 `GainNode`。

做法：
1. **出聲用 Web Audio，並把音訊類別設成「播放」**：在使用者按播放的那一下：`navigator.audioSession.type = 'playback'`（有這個 API 才設）→ 建立／`resume()` 一個 `AudioContext`；每個 `<video>` 接 `createMediaElementSource` → `GainNode`（音量、關聲音都在這裡調）→ 輸出。`<video>` 本身 `muted = false`、音量交給 gain。解鎖一次就好。
2. **沒有 Audio Session API 的舊版 iOS**：不接 Web Audio，直接用 `<video>` 元素出聲（靜音模式下也有聲音），音量只能「有聲／無聲」（`muted`），設定面板上註明「這台手機只能開或關聲音」。不要為了調音量而讓整個聲音在靜音模式下消失。
3. 移除「靜音 play → pause」那段；第一次按播放時，在同一個點擊裡對所有影片元素 `play()`（不靜音）再立刻 `pause()`（同步，不等 promise）。
4. `play()` 失敗不要吞掉：顯示一次「iPhone 擋住了聲音，請再按一次播放」。
5. **不要**提示使用者「關掉靜音開關」。
6. 背景音樂（C 項）同樣走這個 `AudioContext`（已設成「播放」類別），舊版 iOS 則用 `<audio>` 元素。

### A-5 驗收

- e2e：播放 3 秒期間 `EditorBody` 的重畫次數 < 40（用 React Profiler 或計數器）；debug FPS ≥ 50（Chromium，1080p 測試影片）；`compositor` 對影片圖層不再呼叫 `drawImage`（計數器）。
- e2e：有聲音的測試影片（新增 fixture：ffmpeg 產生 440Hz 音調）播放時，`AnalyserNode` 量到音量 > 0；靜音／音量 0 時量到 0。
- 單元測試：有／沒有 `navigator.audioSession` 時，各自走 Web Audio 或 `<video>` 出聲的路徑。
- 🔴 真機：播放是否順、有沒有聲音；**手機切到靜音模式時影片仍有聲音**；音量滑桿在 iPhone 有作用（列入 PLAN §7）。

## B. 匯出影片

規格依 `docs/PLAN.md §2.4`（已定案）：

1. **入口**：頂列加「匯出」鈕 → 底部面板：解析度（1080p／720p）、畫面更新率（30／60）、畫質（標準／高）、預估檔案大小。
2. **影格**：不用 `<video>` 拖時間（慢又不準），改用 Mediabunny 的 `CanvasSink`／`VideoSampleSink` 依時間順序取每個素材的影格；用同一套 `buildScene` ＋ 合成器（離屏，輸出解析度）畫每一格。
3. **聲音**：用 Mediabunny `AudioSampleSink` 解出每個素材的聲音，放進 `OfflineAudioContext` 依時間軸排好（開始時間、修剪、速度、音量、靜音、背景音樂、淡入淡出）一次混好。
4. **編碼與封裝**：先問瀏覽器能不能編 H.264＋AAC（Mediabunny `canEncode`）：
   - 可以 → MP4（H.264 約 10 Mbps、AAC 192 kbps）。iPhone Safari 預期走這條。
   - 不能編 AAC → **先輸出無聲 MP4，並明確告訴使用者**（PLAN 已定：不要偷偷失敗）。
   - 都不能（沙盒 Chromium 沒有 H.264）→ WebM（VP9＋Opus），只給測試用。
5. **大檔**：輸出邊做邊寫進 OPFS（Mediabunny `StreamTarget`），不整支放記憶體。
6. **進度**：進度條＋剩餘時間＋取消；匯出中不能編輯（畫面蓋一層）。
7. **存檔**：完成後「儲存到相簿／分享」用 `navigator.share({ files })`（iPhone 會出現「儲存影片」）；不支援時給下載連結。
8. **驗收**：e2e（WebM 路徑）：2 支影片＋字卡＋貼圖＋聲音的專案匯出 → 用 Mediabunny 在頁面裡讀回：長度一致（±1 格）、解析度正確、有音軌、指定時間的影格顏色和預覽一致；取消會停下來並清掉暫存檔。🔴 真機：MP4／H.264／AAC、1 分鐘影片匯出時間與會不會當掉（PLAN §7 已有）。

## C. 音軌管理＋背景音樂

1. **每支影片的聲音**：剪輯分頁的「音量」改成「聲音」面板：開／關（＝刪除這支影片的聲音）、音量 0–200%、淡入／淡出秒數。疊加軌的影片同樣可設定。軌道選單已有「靜音整條軌」，保留。
2. **「全部影片靜音」**一鍵切換（做 IG 時常用，之後在 IG 裡加音樂）。
3. **背景音樂**：新的軌道種類 `audio`（時間軸最下面一條，顯示波形）。
   - 匯入：「＋ 背景音樂」→ 從「檔案」App 選 mp3／m4a／aac／wav（存在專案裡，跟影片一樣）。
   - 可以拖移開始時間、修剪頭尾、分割、音量、淡入淡出、循環到影片結束。
   - 預覽：用同一個 `AudioContext` 播放（`AudioBufferSourceNode`，依播放頭對時）。
   - 匯出：一起混進 `OfflineAudioContext`。
4. 資料：`AudioItem = { id, type: 'audio', assetId, start, duration, trimIn, volume, fadeIn, fadeOut, loop? }`；`Asset.kind` 加 `'audio'`；`Track.kind` 加 `'audio'`。
5. 波形：匯入時用 Web Audio 解碼一次，存每 50ms 的最大值（小陣列，存在 asset 上）。
6. 驗收：e2e 匯入音樂檔（fixture：ffmpeg 產生 5 秒音調 m4a／wav）→ 時間軸出現音樂軌與波形 → 修剪、音量 → 播放時量到音量；影片聲音開／關。🔴 真機：從「檔案」App 選音樂。
7. 提醒使用者（介面上）：IG 發 Reels 時在 IG 內加熱門音樂比較不會有版權問題（PLAN §Phase 7 已寫）。

## E. 裝飾：長度、透明度、範圍放大；取色彈窗

### E-1 裝飾

1. 新欄位（`src/model/types.ts` 的 `Decoration`，都選填）：
   - `length`：長度，佔文字寬度的比例（0.2–1.5，預設 1），配 `align: 'start' | 'center' | 'end'`（預設置中；尾端圈圈固定從左邊開始）。用在底線類（波浪、虛線、點點、雙底線、尾端圈圈的直線段）、螢光筆。
   - `opacity`：透明度 0.1–1（預設 1）。所有裝飾。
2. **範圍放大**（使用者說幅度太小）：粗細 2%–60%（現在 3–25）、與文字距離 −100%～300%（現在 −30～100）、大小 20%–400%（現在 50–200）、長度 20%–150%。滑桿旁邊顯示數值，數值可以點一下打數字（可選）。
3. `decorations.ts`：底線的 x 範圍依 `length`／`align` 縮放；畫的時候 `globalAlpha = opacity`。尾端圈圈：`length` 只縮短前面的直線段，圈圈大小不變。
4. 驗收：單元測試（長度 0.5 時寬度約一半、三種對齊位置、透明度寫進指令）；e2e 拖長度／透明度滑桿 → 資料與預覽改變；截圖（同一個底線 3 種長度、3 種透明度）。

### E-2 取色彈窗（取代「輸入色碼」）

1. 「更多顏色」裡的「自訂顏色」按鈕 → **跳出彈窗**（`src/ui/ColorPopup.tsx`）：
   - 上方大方塊：橫軸飽和度、直軸亮度，手指**拖拉或點**選顏色（圓形游標）。
   - 下方色相條（彩虹橫條），拖拉換色相。
   - （需要時）透明度條。
   - **RGB 細調**：R、G、B 三條滑桿（0–255），每條旁邊顯示數字和 −／＋ 鈕；拖方塊時三條跟著變，調三條時方塊游標跟著動。
   - 預覽：「原本」和「新的」兩個色塊並排。
   - 「取消」「確定」；確定後加入「最近用過」。
2. 拿掉色碼輸入框（`hex-input`）與系統 `<input type="color">`；色碼只在彈窗裡小字顯示（不能打字）。
3. 全部用 Pointer Events，彈窗內 `touch-action: none`（拖拉時頁面不捲動）；觸控區 ≥ 44px。
4. 所有用到 `ColorPicker` 的地方自動套用（文字、字塊、外框、描邊、裝飾）。
5. 驗收：單元測試（HSV↔RGB 互轉、邊界值）；e2e：開彈窗 → 在方塊上拖 → 顏色改變；調 R 滑桿 → 色碼小字改變；確定 → 套用＋最近用過；取消 → 不變；截圖。
