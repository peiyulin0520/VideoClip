# X6 版型輪流播放（2026-11-15 改寫，Opus 規劃，Sonnet 實作）

取代 `docs/plans/2026-11-14-feedback-12.md` 的「X6」一節。那一節寫在版型 v2 之前，其中「播放軸群組展開」「各格匯入」「版型分頁放特效」已經被 v2（L0～L8）做掉或改掉；**這次只做「輪流播放」本身**。

## 使用者原話（feedback-12 第 15 點，摘要）
版型裡的格子可以「輪流」播：第 1 格播完停住，第 2 格才開始，依序下去；版型頁籤不要放太多東西。

## 現況（v2 架構，動手前先懂）
- 版型＝外框物件（`isFrameItem`，普通影像片段，可在任何影像列）＋格子軌（`groupRole:'cell'`，每格一條，`track.cell` 是格子位置，裡面通常一個格子素材 `item.cell`）＋成員軌（文字、貼圖、音效）。
- 現在的格子是**同時播放**：`importIntoCell`／`applyCell`（`store/actions.ts`）把格子素材的 `start` 設成外框的 `start`，長度最多＝外框長度（`planCell`，`engine/layouts.ts`）。素材比版型短時，播完之後那一格顯示 `track.fill` 色塊（`scene.ts` 的 cell fill）。
- 畫面要畫什麼：`visibleLayers`／`layersAt`（`engine/timeline.ts`）找「t 落在 `[start, start+duration)` 的物件」；`sceneItems`／`buildScene`（`engine/scene.ts`）照它畫。
- 影片要播到哪：`sourceTimeClamped(item, t, asset)`（timeline.ts），預覽 `player.ts` 的 `syncVideo` → `videoSyncPlan`（`videoSync.ts`，已經有「停在第一格／最後一格、不 play()」的 hold）；單格輸出 `exportFrame.ts`、整支匯出 `exporter.ts` 也都用 `sourceTimeClamped`。
- 版型整組搬時間 `moveGroupTo`、改長度 `setGroupDuration`（actions.ts）；版型轉場時格子會延長（`groupTransitions`／`extendForGroupTransition`）。

## 規則（做成什麼樣）
1. **播放方式**二選一，存在外框物件：`VideoItem.layoutPlay?: 'together' | 'sequence'`（沒有＝together，舊專案不變）。
2. **輪流播放**：照「播放順序」一格接一格。第 k 格的 `start`＝外框 `start`＋前面各格長度相加；各格的 `duration` 是**它自己的長度**（不再被外框長度限制）。外框長度＝各格長度相加（自動算）。
3. **停格（不用存，從規則推出來）**：輪流播放的版型，在外框時間範圍內，每一格**一直都看得到**：
   - 還沒輪到 → 顯示它**入點那一格**（靜止）；或者顯示色塊（見 5）。
   - 已經播完 → 停在**最後一格**（靜止）。
   - 停格時**沒有聲音**（聲音只在它自己的 `[start, start+duration)` 出現 —— 混音照原本的 start/duration 算，所以不用改）。
4. **播放順序**：外框物件 `VideoItem.seqOrder?: string[]`（格子軌 id 的順序）；沒有或不完整時用格子軌在陣列裡的順序補齊（`cellTracksOf` 的順序）。
5. **還沒輪到時顯示**：外框物件 `VideoItem.seqIdle?: 'first' | 'fill'`，預設 `'first'`（第一個畫面）；`'fill'` 顯示那一格的色塊（`track.fill`，沒有就用外框顏色）。
6. **空格子**（還沒放素材）：不排進輪流（長度 0），一直顯示原本的空格樣子；放進素材時接到順序最後，長度＝影片自己的長度（最多 10 秒）、照片 2 秒。
7. **切回同時播放**：各格 `start`＝外框 `start`、長度夾在外框長度內（外框長度維持切換前的總長）。一步復原。
8. **改外框長度（拖版型尾端）**：輪流播放時，變長＝結尾多出來的時間所有格子都停在最後一格；變短＝從順序最後面的格子開始切（`setGroupDuration` 原本的「超出結尾切掉」行為）。
9. 版型轉場（L0）：外框轉場的延長／提前那一小段，各格也是停格（提前那段＝入點那一格；延長那段＝最後一格）。

## 步驟

### X6-1 排程與停格（純函式＋單元測試）
新檔 `src/engine/layoutSchedule.ts`：
- `seqOrderOf(project, group): Track[]`：照 `seqOrder` 排好的格子軌（不完整就用陣列順序補）。
- `sequenceSchedule(cells: { id: string; duration: number }[], groupStart: number): { starts: Record<string, number>; total: number }`：空格（duration 0）不佔時間。
- `isSequence(project, group)`、`seqWindow(project, item)`：這個格子素材如果屬於輪流播放的版型，回傳它「看得到」的範圍 `[外框 start − 轉場提前, 外框結束 + 轉場延長)` 與「真的在播」的範圍 `[start, start+duration)`；不是就回傳 null。
- `playTime(project, item, t): { t: number; held: 'before' | 'after' | null }`：把 t 夾進它自己的播放範圍（`after` 夾到 `start+duration − 1/30`）；`held` 讓播放元件知道要停住。
- 測試 `src/engine/layoutSchedule.test.ts`：三格 2/3/1 秒、空格一格 → starts 0/2/5、total 6；順序換了 starts 跟著換；`playTime` 在三種情況的值；`seqIdle:'fill'` 時 before 視為看不到。

### X6-2 引擎接上（畫面、預覽、匯出）
- `layersAt`（timeline.ts）：格子軌這一刻沒有物件在 `[start,end)` 裡，但它屬於輪流播放的版型、t 在 `seqWindow` 看得到的範圍內 → 回傳那一格的素材（停格）。`seqIdle:'fill'` 而且還沒輪到 → 不回傳（讓 scene 的 cell fill 畫色塊；fill 的判斷改成「這一格這一刻沒有要畫的素材」，現有那段已經是這樣）。
  - 注意 `totalDuration` 不受影響（外框長度已經是總長）。
- 影片時間：`sourceTimeClamped` 之前先用 `playTime` 夾 t。改這三個地方：`player.ts` 的 `syncVideo`（`held` 時：`videoSyncPlan` 加參數 `held: boolean` → 直接 `{ hold: true, seekTo: 差超過 0.05 秒才 seek }`，不 play）、`exportFrame.ts`、`exporter.ts`（`vf.frameAt`）。照片不受影響。
- 動態貼圖／GIF 格子（`animImage`）：取格時間也用 `playTime`。
- 定格（keyframes）：格子自己的定格時間以它自己的 start 算，停格時用夾過的 t（`timeResolved` 傳進去的 t 不變，但格子素材取「夾過的 t」的狀態 —— 在 `timeResolved` 裡對 seq 格子用 `playTime(...).t`）。
- 單元測試：`layersAt` 停格、`fill` 模式；`exportFrame` 走 scene，e2e 驗。

### X6-3 動作（store，一步復原）
`src/store/actions.ts`：
- `setLayoutPlay(group, mode)`：切換；`sequence` → 用 `sequenceSchedule` 設各格 start、外框長度＝total；`together` → 規則 7。
- `setCellLength(trackId, seconds, trimIn?)`：輪流播放時改一格的長度（`CellSheet` 拖起迄、播放軸拖格子片段右邊）；重排後面各格、外框長度跟著變。影片長度不能超過素材剩下的長度；最短 0.2 秒。
- `setSeqOrder(group, order)`、`setSeqIdle(group, idle)`。
- 既有函式要顧到輪流播放：
  - `importIntoCell`：輪流播放時照規則 6 接到最後（並重排）。
  - `applyCell`（這一格視窗的「素材比這一格短／長」）：輪流播放時不用 `planCell` 夾到外框長度，`L`＝這一格自己的長度。
  - `setGroupDuration`：規則 8。
  - `moveGroupTo`：整組平移（現在就是，不用改）。
  - 刪掉一格素材（`removeAnyItem` 等）：輪流播放時重排（後面的往前補）。
- 單元測試 `src/store/layoutSequence.test.ts`：切換來回（一步復原）、改第 1 格長度 → 第 2、3 格 start 往後、總長變；換順序；空格放素材後接到最後；改外框長度變短從最後一格切。

### X6-4 介面
- **版型分頁**（`tabs/LayoutTab.tsx`，GroupPanel 裡，示意圖下面，一個 `.zone-soft` 區塊「播放方式」）：
  - 二選一 chips：「同時播放」「輪流播放」（radio，aria-label `播放方式 同時播放`／`播放方式 輪流播放`）。
  - 輪流播放時多一列「還沒輪到時」：「第一個畫面」「色塊」。
  - 播放順序：示意圖每一格左上角顯示順序數字（`LayoutDiagram` 加 badge）；改順序在「這一格」視窗。
  - 這些是版型才有的設定，所以放版型分頁（不放特效分頁）。立刻生效、可復原（跟外框顏色一樣，不是彈出視窗，不需要「套用」）。
- **這一格視窗**（`CellSheet.tsx`，已有「套用／儲存」）：輪流播放時：
  - 「片段」那段的起、迄**都可以拖**（長度＝這一格的長度，不再固定＝外框長度），下面寫「這一格播 X 秒，第 N 個播」。
  - 「第幾個播」：－／＋ 步進（1～格子數），按「套用」才生效（存進 `seqOrder`）。
  - 「素材比這一格短／長」那塊在輪流播放時隱藏（長度就是素材想要的長度）。
- **播放軸**（`Timeline.tsx`，版型展開後的「影像」子分類，每格一列，現有）：
  - 輪流播放時每格的片段自然排成階梯（各自的 start）；**停格的部分畫成淡色斜線延伸**（`.clip-hold`，在片段前後，到外框的頭尾），一眼看出「這段是停住的」。
  - 拖格子片段右邊＝`setCellLength`（後面的格子跟著往後推）；輪流播放時拖格子片段本體左右**不行**（toast「輪流播放時用『這一格』視窗改順序」）。
  - 版型那一條（外框片段）上加小字「輪流」標記（在片段名稱後面），收合時也看得出。

## 驗收
- 單元：X6-1、X6-3 列的全部；`videoSyncPlan` 的 `held` 分支。
- e2e 新檔 `e2e/x6-sequence.spec.ts`：
  1. 三格版型（紅、綠、藍各 2 秒影片，用 `tests/fixtures` 的純色 WebM），版型分頁切「輪流播放」→ 外框長度 6 秒；播放軸三格是階梯（start 0/2/4 相對外框）。
  2. 第 1 秒：第 1 格在動（`__videoclip` 取那一格的來源時間 ≈ 1 秒）、第 2、3 格看得到且是第一個畫面（取樣格子中間是綠／藍）；第 3 秒：第 1 格停在最後一格（還是紅）、第 2 格在播；第 5 秒：三格都有畫面。單格輸出第 3 秒的三個格子中間顏色跟預覽一樣。
  3. 切「還沒輪到時：色塊」→ 第 1 秒時第 3 格中間是色塊顏色。

## 風險
- iPhone 同時解碼的影片數（`MAX_CELL_VIDEOS`）：輪流播放時停格的影片是暫停的，比同時播放輕；但元件還是開著。超過 5 格影片照舊提醒。
- 停格在最後一格要 seek 到 `duration − END_HOLD`（`videoSync.ts` 已有），iPhone 上第一次停格可能閃一下；e2e 只在 Chromium，要列進 iPhone 驗收。
