## 0. 使用者原話重點

1. 時間軸左邊的軌道圖示：**長按其中一個 → 進入多選**，可以一次改多個圖層的順序、一次刪除多個、還可以「整併」。
2. **刪掉動態模板**（「很爛」，自己用特效＋圖層做就好）。新增特效「**捲簾放下**」「**捲簾收合**」；轉場參考 Insta360（分類：基本／相機動作／特效／故障／自然／其他；有「全域應用」；長度滑桿 0.5s）；**每個轉場選項要有用 A→B 示意的動畫**。
3. 音訊分頁每一列寫「影片」看不出是哪一支 → **用各影片的首圖**顯示。
4. 修剪面板的小預覽**太卡、會跳格**，看不出保留的是什麼；**音訊也要有同樣的修剪**（上方旗標）。
5. GIPHY 搜尋只有 24 個 → 往下滑**載入更多**。
6. 版型＋動畫（使用者叫「轉場特效」）會跑版：影片沒有一直在格子裡；播放卡（可以降低預覽畫質，但**匯出不能受影響**）；**已經刪除的圖層，預覽還看得到它的素材**。
7. 裁切的工具列（自由形狀／重設／取消／完成）在淺色主題是黑底深色字看不到；自由形狀裁完之後，要能用**筆刷補回**要留的地方、**橡皮擦擦掉**多的地方，兩個都要能調粗細。

## H1. 修 bug（6、7、3、5）

### H1-1 已刪除的圖層還出現在預覽（6）——**已找到原因**
- 「剪輯 → 刪除並補齊」走 `rippleRemoveItem`，**不認得版型**：刪的是外框時只刪外框，各格還在（各格的軌道在時間軸上是藏起來的 `groupRole:'cell'`），所以時間軸上看不到、預覽卻還在畫。圖層分頁的刪除也要查同樣的問題。
- 這些「孤兒格子」還會佔掉預覽的影片池（`POOL_SIZE`），新的版型格子因此拿不到 `<video>`，**格子變黑**——使用者截圖裡膠卷三格全黑就是這個。
- 做法：
  1. 所有刪除路徑（`rippleRemoveItem`、圖層分頁的刪除、之後 H5 的多選刪除）遇到 `groupRole:'frame'` 一律走 `removeGroup`；刪單一格子＝只把那一格換成「空位」（色塊），不拿掉軌道。
  2. 新增 `repairGroups(project)`（在 `migrateProject` 之後、每次讀專案時跑；也在 `removeGroup` 之後跑）：**有 cell 沒有 frame 的 group → 把那些軌道的 `group/groupRole/fill` 清掉、`item.group/cell` 清掉**，變回普通影像軌，時間軸看得到、使用者可以自己刪。使用者目前的專案打開後就會修好。
  3. 單元測試：刪外框（三種路徑）後專案裡沒有該 group 的任何物件；`repairGroups` 把孤兒格子變回普通軌道。

### H1-2 版型跑版（6）
- 已找到一個原因：圖層分頁「位置、大小、旋轉歸位」直接改 `transform`（`LayersTab.tsx` 約 160 行），沒走 `setTransform`，版型裡的某一格或外框被單獨歸位就跑版。改成：版型物件按這顆＝整組歸位（`setTransform(frameId, {x:.5,y:.5,scale:1,rotation:0})`）。
- 透明度滑桿（同檔 108 行）也直接改：版型改成整組透明度。
- 全面搜 `transform.` 的直接寫入（`grep -rn "transform\.\(x\|y\|scale\|rotation\) *=" src`），版型物件一律走 `setTransform`。
- 加一個保險：`buildScene` 畫版型的格子時，若格子的 `cell` 套上外框 transform 的位置跟格子目前位置差太多（>2% 畫面），**以外框為準重算**（用 `composeWith(cellTransform(...), frame.transform)`），並在開發模式 console 警告。這樣就算有漏網的路徑，畫面也不會跑版。
- 動畫（捲動／滑入滑出）時格子跟外框一起位移本來就有做；e2e 加一個「捲動動畫中，每一格的中心取樣都在外框的洞裡」的測試（取 3 個時間點）。

- 裁切模式時隱藏預覽右上的「圖層」按鈕（截圖裡它跟「完成」擠在一起）。

### H1-4 音訊分頁每一列顯示首圖（3）

## H3. 預覽順暢（6、4）

### H3-1 預覽畫質（流暢模式）
- 設定頁＋預覽右上「⋯」選單：**預覽畫質：自動／清楚／流暢**（存這台手機，`vc-preview-quality`）。
  - 清楚＝現在的解析度；流暢＝合成器畫布 0.5 倍（`app.renderer.resolution` 或畫布像素寬高減半，CSS 大小不變），影片一律用預覽檔（proxy，沒有的先排隊做）；自動＝同時畫的影片 ≥ 3 支、或最近 2 秒平均每秒不到 24 格時自動切到流暢，畫面右上角小字「流暢預覽」。
- **匯出完全不受影響**：匯出走自己的合成器與輸出解析度（`exporter.ts`），只在 Player 用這個設定；e2e 驗證「流暢模式下匯出單格的大小與顏色跟清楚模式一樣」。

### H3-2 同時影片太多
- 預覽影片池滿了（`pool.acquire` 回 null）時，現在是那一格不畫（變黑、看起來像壞掉）。改成：
  1. 優先順序：最上層、面積最大的先拿到；
  2. 拿不到的畫**那個素材的縮圖**（`asset.thumbs` 依時間挑最近的一張，靜態圖），角落小字不需要；
  3. 第一次發生時跳一次提示「同時播放的影片太多，有些格子先用縮圖預覽；匯出不受影響」。
- 匯出時不受池的限制（逐格解碼）。

### H3-3 修剪面板的預覽不卡（4）
- 原因：拖旗標時每一下都 `player.peek()` 讓 `<video>` seek，手機上 seek 很慢，畫面跟不上就跳。
- 改成兩段式：**拖的時候**小畫面顯示**素材縮圖**（`asset.thumbs` 已經有一排，挑最接近的一張，零延遲）；**放開後**才 seek 到精準的那一格（`requestVideoFrameCallback` 到了才換掉縮圖）。
- 縮圖太疏（長影片每 1 秒一張以下）時，進入修剪面板背景補抽（Mediabunny，最多 60 張，跟時間軸縮圖共用快取）。
- 小畫面加大成 120px 高，並在下面標示「第 3.2 秒」；旗標上方顯示「起點 0:03.2」「終點 0:07.0」。
- 加「▶ 播放這一段」按鈕：只播目前選的這一段（播到終點自動停）。

## H5. 軌道多選（1）
- 進入多選：**長按軌道圖示 500ms 且手指沒有移動**（震動一下）→ 進入多選，這一條打勾。現在「按住圖示上下拖＝換順序」維持：手指移動超過 8px 就是拖（不會進入多選）。
- 多選模式：
  - 每個軌道圖示變成勾選框（再點一下切換）；時間軸上方出現一條動作列：「已選 N 條｜上移｜下移｜整併｜刪除｜完成」。
  - **上移／下移**：選到的軌道各自在自己的分區內往上／下一格，保持彼此的相對順序；碰到分區頂端的那條不動。也可以按住任一條選到的圖示上下拖，**選到的全部一起移**（放下時插在同一個位置，保持相對順序）。
  - **刪除**：一步刪掉所有選到的軌道（版型外框＝整個版型）；至少留一條影像軌；一步復原。
  - **整併**：把選到的**同一種類**軌道合成一條（放在最上面那條的位置）。物件時間重疊時：重疊的那幾個放不進去 → 留在原軌道，提示「有 2 個時間重疊，留在原本的軌道」。不同種類混選時「整併」反灰並說明。版型的軌道不能整併（反灰）。
  - 「完成」、點時間軸空白處、切分頁 → 離開多選。
- 收合狀態（G2）時長按會先展開全部。
- 單元：`moveTracksBy(ids, ±1)`、`mergeTracks(ids)`（含重疊留下）、`removeTracks(ids)`；e2e：長按進多選、選 3 條、上移、整併、刪除、復原。

## H6. 轉場 v2（2）

### H6-1 引擎：前後兩段真的重疊
現在的轉場是「前半在前一段、後半在後一段」，推／升中間會黑一下，也做不出疊化、捲簾、分割這類需要兩段同時出現的效果。改成：
- 轉場期間 `[接縫 − d/2, 接縫 + d/2]`，**前一段延長**到接縫後 d/2（用素材在出點之後的畫面；沒有就停在最後一格）、**後一段提前**從接縫前 d/2 開始（用入點之前的畫面；沒有就停在第一格）。時間軸上的片段長度、位置都不變（只是轉場期間多畫一層）。
- 實作：`buildScene` 在轉場期間多產生一個「虛擬物件」（同一個素材，`id: 原id + '#tr'`、`start/trimIn` 調好、超出素材範圍就夾住）；Player 的影片池用這個 id 再拿一個 `<video>`（預載：接縫前 1 秒先準備）；匯出的 provider 本來就是依 `item.start/trimIn` 算解碼時間，夾住即可。
- 每個轉場是一個純函式 `transitionFrame(kind, p) → { a: Look, b: Look, covers: Cover[] }`，`Look = { dx, dy, scale, rotation, opacity, clip?: Rect, blur?: number, rgbSplit?: number, slices?: … }`，a＝前一段、b＝後一段，p 0→1。
- 合成器要多支援：`clip`（畫面座標的矩形或圓形遮罩，Pixi `Graphics` mask）、`blur`（Pixi `BlurFilter`，強度 0–20）、`rgbSplit`（簡單自訂 filter：R、B 通道左右錯開）。手機上 filter 很吃效能：流暢模式（H3）時 blur 改成「縮小再放大」的便宜做法。

### H6-2 轉場清單（我們自己的名稱與畫法）
| 分類 | 轉場 | 怎麼做（a＝前一段、b＝後一段） |
|---|---|---|
| 基本 | 無、疊化（淡入淡出）、閃黑、閃白、過曝、放大疊化 | 疊化：a 透明度 1→0、b 0→1；閃黑／閃白：顏色層；過曝：顏色層白＋a、b 亮度（`brightness` filter，沒有就用白色 add 混合）；放大疊化：a 放大 1→1.3 同時淡出、b 淡入 |
| 基本 | 左移、右移、上移、下移 | a、b 同時往同方向推（真正的推，不再先出後進） |
| 基本 | **捲簾放下**、**捲簾收合** | 放下：b 的 `clip` 從上往下展開（0→100% 高），邊緣一條 6px 柔邊陰影；收合：a 的 `clip` 從下往上收起來露出 b |
| 基本 | 中心擴散、上部擴散、下部擴散 | b 的圓形／矩形 `clip` 從中心（或上、下）擴大 |
| 基本 | 虛焦、模糊轉場 | a 模糊 0→20 淡出、b 20→0 淡入；虛焦再加一點放大 |
| 相機動作 | 極速左移、極速右移、向左滑動、向右滑動、向上滑動、向下滑動 | 推移＋動態模糊（橫向 blur），極速＝曲線前慢後快 |
| 相機動作 | 縮放進、縮放出 | a 放大 1→2 淡出 → b 從 0.5→1 |
| 特效 | 暖色閃光（沿用）、膠片上移、膠片左移 | 膠片：程式畫兩條有齒孔的黑邊帶跟著畫面一起捲動（沿用 `layouts.ts` 的齒孔畫法） |
| 特效 | 四宮格、九宮格 | b 切成 2×2／3×3 塊，依序從小放大出現（每塊一個 `clip`） |
| 故障 | 干擾、故障 1、故障 2 | `rgbSplit` 強度跳動＋水平切片錯位（`slices`：把畫面切成 6–10 條各自左右位移），接縫時最強 |
- 「自然」（海水、雪景）需要真實素材，**不做**；「其他」先空著不顯示。
- 舊的七種（淡、黑、白、閃、推、升、縮）對應到新名稱（推→左移、升→上移、縮→縮放進），舊專案的 `kind` 直接轉換。

### H6-3 選單樣子（參考 Insta360 的排法）
- 特效分頁 → 轉場：上面一排**分類**（第 3 層膠囊：基本／相機動作／特效／故障），下面一排**可以左右滑的方形卡片**（64×64），卡片下面是名稱；第一張是「⊘ 無」。
- **每張卡片是一個小動畫**：用兩張我們自己畫的示意圖（A：暖橘色漸層＋大字「A」；B：藍綠色漸層＋大字「B」），用同一個 `transitionFrame` 在 2D canvas 上畫出 A→B 的過程，1.6 秒循環（轉場 1 秒＋停 0.6 秒）。只有在畫面上看得到的卡片才動（`IntersectionObserver`），同時最多動 8 張；`prefers-reduced-motion` 時只畫 p=0.5 那一格。
  - 2D canvas 版本要支援：位移、縮放、透明度、矩形／圓形 clip、顏色層；blur 用 `ctx.filter = 'blur()'`（Safari 不支援就跳過）；故障用切片錯位畫。不用跟正式畫面一模一樣，但看得出是什麼效果。
- 選中的卡片：粗外框（主題強調色）；選了之後下面出現**長度滑桿 0.2–2.0 秒**（取代現在的四個長度按鈕）和右下角「**全部套用**」（＝套用到這一軌所有銜接處，沿用 `setTransitionAll`）。
- 時間軸上的小圓圈代號改成每種轉場一個字（疊、黑、白、曝、移、捲、擴、糊、速、縮、閃、膠、格、故…），對照表放在 `transitions.ts`。

### H6-4 驗收
- 單元：每種轉場在 p=0、0.5、1 的 a／b 狀態（p=0 只有 a 完整、p=1 只有 b 完整）；虛擬物件的 `trimIn` 夾在素材範圍內。
- e2e：紅、綠兩段 → 疊化在接縫取樣是紅綠混色（不是黑）；捲簾放下在接縫時上半綠、下半紅；左移在接縫時左半紅、右半綠；匯出單格跟預覽一致（這幾個時間點）。卡片動畫：卡片 canvas 在兩個時間點的像素不同。
- 🔴 iPhone：兩支影片同時解碼的轉場順不順；filter（模糊、故障）在 iPhone 的效能。

## H7. 裁切：筆刷補、橡皮擦擦（7）
- 自由形狀圈完之後（或任何裁切狀態），工具列多兩顆：「**筆刷（留下）**」「**橡皮擦（去掉）**」，下面一條**粗細滑桿**（畫面寬度的 1%–15%，預設 4%），預覽上手指畫過的地方即時變成留下／去掉；「重設」回到圈選的形狀。
- 資料：遮罩從多邊形改成**點陣圖**：`VideoItem.maskBitmap?: string`（PNG data URL，以素材畫面為座標，長邊最多 1024px，灰階 alpha），有它時優先於 `mask`（多邊形）。第一次用筆刷時把多邊形畫成點陣圖再開始改。邊緣 1.5px 柔化（畫的時候用 `shadowBlur`，或存檔前做一次模糊）。
- 畫法：筆刷在素材座標上畫圓形連續筆觸（兩點之間補點），橡皮擦用 `globalCompositeOperation = 'destination-out'`；每一筆放開＝一步復原（完成前在裁切模式自己的復原堆疊，按「完成」才整個寫進專案一步）。
- 合成器：點陣圖遮罩用 Pixi sprite mask（同一張貼圖，素材變形時跟著）；匯出同一套。
- 畫的時候顯示：留下的部分正常、去掉的部分半透明紅色蓋著（像 Photoshop 快速遮罩），讓使用者看得到範圍；筆刷游標畫一個圓圈顯示大小。
- 手勢衝突：筆刷模式時單指＝畫、雙指＝縮放預覽中的畫面（只在裁切模式內）。
- e2e：圈一個框 → 用橡皮擦在中間畫一筆 → 完成 → 預覽中間取樣是透明（底下的顏色）；筆刷補回 → 有顏色；粗細滑桿改變後同樣一筆的影響寬度不同。
- 🔴 iPhone：手指畫的順暢度、1024px 遮罩的記憶體。
