## J1. 調色引擎

### 資料（`src/model/types.ts`）
`Adjust` 擴充（每項 −1～+1，0＝不變；舊專案只有前四項，其他當 0，不用轉換）：

| 欄位 | 名稱 | 做法（著色器裡的順序就是這張表的順序） |
|---|---|---|
| `exposure` | 曝光 | 線性光乘 `2^(exposure × 2)`（±2 格光圈） |
| `temperature` | 色溫 | 冷↔暖：R ×(1+0.3t)、B ×(1−0.3t)（沿用 I7） |
| `tint` | 色調 | 綠↔洋紅（沿用 I7） |
| `contrast` | 對比 | 以中灰 0.5 為軸：`(x − 0.5) × (1 + c) + 0.5`（c<0 時是 ×(1+c)，最低 0.2 倍） |
| `highlights` | 高光 | 只動亮部：權重 `smoothstep(0.5, 1.0, luma)`，`x += h × 0.35 × 權重 × (h<0 ? x : 1−x)` |
| `shadows` | 陰影 | 只動暗部：權重 `1 − smoothstep(0.0, 0.5, luma)`，同上（正＝提亮暗部） |
| `blacks` | 黑點 | 正＝黑色變灰（褪色／霧面）：`x = b×0.25 + x×(1 − b×0.25)`；負＝黑色更黑：`x = max(0,(x − |b|×0.15)/(1 − |b|×0.15))` |
| `brightness` | 亮度 | 中間調為主（gamma）：`x = x^(1/(1 + b×0.6))`（I7 原本是整體乘，改成這個比較自然；舊專案的亮度值照新算法，差異可接受） |
| `saturation` | 飽和度 | 跟灰（Rec.709 亮度）之間內插：`mix(luma, x, 1 + s)` |
| `vibrance` | 鮮艷度 | 越不飽和的顏色加越多、已經很飽和的（含膚色）少加：`amt = v × (1 − 目前飽和度)`，再用飽和度公式 |
| `fade` | 褪色 | 整體往 0.5 灰拉一點、暗部抬起（復古／日系用）：`x = mix(x, 0.5 + (x−0.5)×0.7, fade)` 只允許 0～1 |

- 計算一律在 0～1、最後夾住；不做真正的線性／sRGB 轉換（手機效能與一致性優先），曝光用近似。
- `ADJUST_KEYS` 擴充成 11 項：`adjustAt`（定位漸變）、`upsertKeyframe`、`fullAdjust`、`isZeroAdjust` 全部跟著用新清單，不用改邏輯。

### 參考實作（`src/engine/grade.ts`，純函式＋單元測試）
- `gradeRGB([r,g,b], adj): [r,g,b]`：跟著色器一模一樣的算式（JS 版）。用途：①單元測試 ②預設卡片的小縮圖（CPU 對 64px 縮圖算一次）。
- `gradeUniforms(adj)`：轉成著色器要的 uniform（11 個 float）。
- `isNeutral(adj)`：全部 0 → 不加濾鏡。

### 著色器濾鏡（`src/engine/gradeFilter.ts`）
- Pixi v8 `Filter`＋`GlProgram.from({ vertex: 預設, fragment })`，一個 pass 做完上表全部；uniform 一組 `gradeUniforms`。合成器已經是 `preference: 'webgl'`，所以只寫 GLSL（不用 WGSL）；在檔案開頭註明「如果改成 WebGPU 要補 gpuProgram」。
- 注意 Pixi 濾鏡給的是**預乘 alpha** 的顏色：先 `rgb /= a`（a>0），算完再乘回去，不然貼圖、字卡邊緣會發黑。
- `compositor.ts`：把 `ColorMatrixFilter` 換成 `GradeFilter`（每個圖層一個，`isNeutral` 時拿掉；跟模糊濾鏡並存，順序：調色 → 模糊）。`keyframes.ts` 的 `adjustMatrix` 刪掉（測試改成測 `gradeRGB`）。
- 預覽、單格輸出、整支匯出都走合成器 → 三者一致，不用另外處理。

### 驗收（J1）
- 單元（`grade.test.ts`）：全部 0＝原色；飽和度 −1 → r=g=b；曝光 +0.5 → 中灰變亮約 2 倍（夾住）；對比 + → 亮的更亮暗的更暗、0.5 不變；高光 − 只動亮部（暗部像素不變）；陰影 + 只動暗部；黑點 + → 純黑變灰、黑點 − → 深灰變黑；鮮艷度：低飽和顏色變化比高飽和大；褪色 → 純黑抬起；`gradeUniforms` 的順序與數量。
- e2e：紅色影片飽和度 −100 → 灰（I7 的測試照舊要過）；曝光 +50 → 預覽與單格輸出同一點顏色相同；貼圖（透明邊）調色後邊緣不發黑（取樣透明區還是透明）。

## J2. 色調組合（預設）

### 資料
- `ItemBase.look?: { id: LookId; amount: number }`（`amount` 0～1，預設 1）。預設是一組 `Adjust` 值；**實際用的值＝預設值 × 強度＋手動調整**（各項相加後夾在 −1～1）。手動滑桿永遠是「在預設之上再微調」。
- 定位：預設本身不打在定位上（整個片段同一個預設）；手動的調整照 I7 可以打在定位上漸變。
- `engine/grade.ts` 加 `LOOKS` 目錄與 `effectiveAdjust(item, adjustNow)`；`scene.ts` 的 `toLayer` 用 `effectiveAdjust` 算出最後的值交給合成器。

### 驗收（J2）
- 單元：`effectiveAdjust`（預設×強度＋手動、夾住）；每個預設對「中灰」「膚色」「天空藍」三個顏色的 `gradeRGB` 結果符合描述（黑白 r=g=b；冷色調 b>r；暖色調 r>b；復古的純黑被抬起；鮮豔的低飽和色變比較飽和）。
- e2e：紅色影片套「黑白」→ 預覽灰色、單格輸出同一點一樣；強度拉到 0 → 回到紅色；再手動飽和度 +50 疊在預設上。

## J3. 介面

### 剪輯分頁加「調色」按鈕 → 調色面板（`src/app/editor/ColorPanel.tsx`）
- 影片、照片、貼圖、字卡都能用（音樂沒有）；版型的任何物件＝整個版型（跟 I7 的 `setAdjust` 一樣，外框有定位就打在外框的定位上）。
- **上半：色調組合卡片**（橫向捲動）：「原圖」＋ 9 個預設。卡片是**這個素材自己的縮圖**套上預設（用 `gradeRGB` 在 64px 縮圖上算，結果快取），下面寫名稱；選到的有粗外框。選了之後出現「強度」滑桿（0～100%）。
- **下半：調整滑桿**（−100～+100，雙擊或點數值歸零）：曝光、對比、高光、陰影、黑點、亮度、飽和度、鮮艷度、色溫、色調、褪色（0～100）。滑桿有定位時標「（定位）」，改的是播放頭這個時間的定位（I7 行為）。
- 按鈕：「**按住看原圖**」（按住時預覽暫時不套調色，`Player.setPreviewPatch` 把這個物件的 `adjust`、`look` 拿掉）、「全部歸零」、「**套用到全部片段**」（同一類的所有片段都用同一組預設與調整，一步復原）。
- 定位面板（`KeyframePanel`）的四條色調滑桿拿掉，改一行字「調色在 剪輯 › 調色（有定位時可以漸變）」，點了直接打開調色面板。
- 時間軸：有調色的片段在名稱後面加一個小「調」字（跟「靜音」一樣的位置），方便知道哪些有調。

### 驗收（J3）
- e2e：剪輯分頁 → 調色 → 卡片 10 張（含原圖）、卡片縮圖顏色不同（黑白卡片 r≈g≈b）→ 點「復古」→ 強度 50% → 項目值寫進 `look`；拖「曝光」→ `adjust.exposure`；「按住看原圖」時預覽回到原色、放開恢復；「套用到全部片段」兩個片段都有同樣的 `look`、一步復原；定位：開頭打定位、3 秒處把飽和度拉到 −100 → 漸變（I7 的測試改成從調色面板操作）。
- 截圖：`docs/screenshots/color/`（面板、每個預設套在測試影片上）。

## 不做／之後
- 曲線（RGB curves）、HSL 分色調整、分離色調（高光陰影各自上色）、LUT 匯入（.cube）、暗角、顆粒——之後可以加在同一個著色器裡。
- 自訂預設（把目前的調整存成自己的色調組合）——先問使用者要不要。
