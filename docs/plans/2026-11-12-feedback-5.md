## P. 播放還是很卡（最優先）

### P-1 錄影量到的事實

錄影三（60fps 螢幕錄影）逐格比對：**預覽、時間軸、時間數字三個區域都大約每 17–25 格才變一次 ≈ 每秒 3 次**。連時間軸都一樣卡 → 不是只有影片解碼慢，是**每一格的 JavaScript 主執行緒工作要 ~300ms**（rAF 一秒只跑得到 3 次）。

Chromium（沙盒）同一套程式每格合成 ≈1.3ms，所以是 **iPhone 特有**的慢。最可能的原因（依可能性排序）：

1. **iPhone 拍的影片是 HDR（HLG／Dolby Vision 10-bit）、HEVC、常常 4K**。Safari 把這種影片的一格交給 WebGL（`texImage2D(video)`）或 2D canvas（`drawImage(video)`）時，要在 CPU 上做 10-bit HDR → 8-bit SDR 的色彩轉換、還要整張 4K 搬運 → 一格幾百毫秒。之前（暫存畫布）和現在（直接貼圖）都會經過這一步，所以 PR #6 改完還是卡。
2. 每格 `buildScene` 重新算字卡／貼圖（應該有快取，要量）。
3. `playbackRate` 微調在 iOS 上會讓影片解碼卡一下（要量；若是，iOS 上關掉微調）。

### P-2 改法

**P-2a 先讓 iPhone 自己說哪裡慢（小、先做）**
- 設定頁加「顯示播放效能」開關（存 localStorage `vc-perf`，跟 `vc-debug` 分開，給使用者用）。打開後預覽左上角一個小黑框：`畫面 3.1 fps｜每格 312ms（影片上傳 290、字卡 4、其他 18）｜影片 3840×2160 HEVC HDR｜掉格 41`。
  - 分段計時：`Player.render()` 裡 `buildScene`、`compositor.update` 各影片圖層（`textureSource.update()` 前後）、`renderer.render` 分開量。
  - 影片資訊：匯入時已經用 Mediabunny 讀容器（`probeVideoContainer`），順便存 `asset.codec`、`asset.hdr`（`track.hasHighDynamicRange()`）、`asset.fps`；掉格用 `el.getVideoPlaybackQuality()`。
- 使用者錄一段打開效能框的播放給我們，就能確定是哪一段。

**P-2b 預覽用的輕量影片（Proxy，主要解法）**
- 匯入影片時，若「長邊 > 1280」或「HDR」或「不是 H.264」，在背景用 Mediabunny `Conversion` 另外做一份**預覽用影片**：H.264、長邊 960（跟預覽解析度一樣）、SDR 8-bit、30fps、約 3 Mbps、聲音直接複製（AAC 不重新編碼；不能複製就轉 AAC 128k）。
  - HDR → SDR：`video.process` 回呼裡把 `VideoSample` 畫到 OffscreenCanvas（canvas 會轉成 sRGB）再交給編碼器；只在 `hasHighDynamicRange()` 為 true 時這樣做（不然直接 `width/height` 縮小即可）。
  - 存在 OPFS／IndexedDB，跟原檔同一套 `putMedia`，key `proxy:<assetId>`；`Asset.proxy?: { status: 'pending' | 'ready' | 'failed'; width; height }`。
  - **預覽播放用 proxy、匯出用原檔**（`urlFor(assetId, { purpose: 'preview' | 'export' })`）。proxy 還沒好時先用原檔，時間軸片段上顯示小字「預覽檔製作中 42%」。
  - 匯入流程不要等 proxy 做完（素材先出現、可以先剪），proxy 依序一支一支做，做完自動換掉（`player.refresh()`）。
  - 失敗（例如手機不支援 H.264 編碼）→ 照用原檔，設定頁效能框顯示「預覽檔做不出來」。
  - 設定頁「儲存空間」把 proxy 算進去，並提供「清除預覽檔（之後會重做）」。
  - 已經存在的專案：開啟時發現影片沒有 proxy → 背景補做。
- 這也讓之後的「匯出」和「多格模板」同時播放多支影片比較撐得住。

**P-2c 小修**
- 合成器：影片圖層只有在 `requestVideoFrameCallback` 說「有新的一格」時才上傳（現在是比 `currentTime`；iOS 的 `currentTime` 可能每次都不同 → 每次都上傳）。
- iOS 上關掉 `playbackRate` 微調（只保留超過 0.5 秒硬跳），用 P-2a 的數字確認有沒有差。
- 時間軸自動捲動改成每 2 格捲一次或用 CSS transform（量了再說）。

### P-3 驗收
- 單元：proxy 判斷條件（長邊、HDR、codec）、`urlFor` 用途選擇。
- e2e（Chromium）：匯入 1920×1080 的測試影片（新 fixture：ffmpeg 產生 1080p VP9 webm，Chromium 會轉成 960 的 proxy）→ 等 proxy ready → 播放器用的是 proxy URL、尺寸 960；proxy 失敗（mock 編碼器丟錯）→ 照常播放原檔；效能框開關會顯示數字。
- 🔴 真機（最重要）：同一支 iPhone 原生影片，效能框的 fps 從 ~3 變 ≥ 24；匯入後多久 proxy 做好（8 秒影片）。

## T. 主軌修剪（錄影一、二）

### T-1 現在為什麼會那樣（已查證）
- 主軌是「磁吸」排法（`engine/timeline.ts` `relayout`：片段一個接一個從 0 秒開始）。把**左把手往右拉**＝切掉片段開頭（`trimStart` 讓 `trimIn` 變大、`duration` 變小），但因為片段永遠從前一段的尾巴開始，畫面上看起來就是「右邊縮回來」。
- 右把手只能把**尾巴**拉回來（最多到素材結尾），切掉的開頭只能用左把手往左拉回來 → 使用者以為「拉不回來」。

### T-2 改法

**T-2a 主軌允許空白（使用者：「前面幾秒沒有影片也可以」）**
- `VideoItem` 加 `gap?: number`：這個片段**前面**的空白秒數（主軌才用）。`relayout` 改成 `t += gap; start = t; t += duration`。空白的地方預覽是黑畫面（疊加、文字照常顯示）。
- 主軌左把手：
  - 往右拉：切掉開頭，**片段尾巴不動**，前面多出空白（`trimIn += d`、`duration -= d`、`gap += d`）。後面的片段都不動。
  - 往左拉：先吃掉前面的空白（片段往左長回來、尾巴不動）；空白用完後，再往左＝把開頭拉回來並把後面的片段往後推（原本的行為），最多拉回素材起點。
- 右把手：同現在（尾巴拉長／縮短，後面片段跟著移）。
- 空白在時間軸上顯示成虛線框「空白 1.2 秒」；點空白 → 剪輯工具列出現「刪除空白」（`gap = 0`，後面往前接上）。
- `totalDuration`、`itemAt`、`splitItem`、`moveItem`（換順序時空白跟著片段走）都要處理 `gap`；單元測試補齊。

**T-2b 「修剪」面板（照錄影二的方式）**
- 選到主軌或疊加的影片 → 剪輯分頁多一個「修剪」按鈕 → 面板打開：
  - 一條**整段素材**的縮圖條（素材從頭到尾，不是只有目前留下的部分），有聲音的話下半部疊一條聲音波形（之後音軌 C 項的波形共用；這次沒有波形也可以，先只做縮圖）。
  - 中間一個**選取窗**：左右兩個粗的深色把手（≥ 44px 寬的觸控區），窗外變暗。拖把手＝選要留下的區段；拖窗中間＝整段平移（長度不變，換一段內容）。
  - 下面一行：「第 2.0 秒 → 第 6.2 秒　留 4.2 秒／素材共 12.0 秒」。
  - 按鈕：「前面多 1 秒」「前面少 1 秒」「後面多 1 秒」「後面少 1 秒」（各 0.1 秒精調可以長按連續）。
  - 拖的時候預覽畫面跟著顯示把手那一格（`player.peek`，已有）。
  - 「完成」關閉；全程一次復原（coalesce `trim:<id>`）。
- 資料就是現有的 `trimIn`／`duration`（加上 T-2a 的 `gap` 規則：主軌改開頭時尾巴不動、留空白）。
- 時間軸上的左右把手保留（快速調），行為跟 T-2a 一致。

### T-3 驗收
- 單元：`gap` 的 `relayout`／`trimStart` 往右再往左完全回到原狀／`totalDuration`／分割有空白的片段／換順序／刪除空白。
- e2e：錄影一的操作重現 → 左把手往右拉後片段尾巴位置不變、前面出現「空白」、再往左拉回到原本長度；修剪面板：拖左把手、拖右把手、拖窗中間、四個按鈕、文字顯示正確、一次復原；截圖。
- 🔴 真機：把手好不好抓、預覽跟著顯示。

## B. 字塊：填滿和框線分開

### B-1 現況
- `CardBox` 只有一個 `fill`＋一個 `opacity`，而且 `opacity` 同時套在填滿**和**外框上（`textRender.ts` 外框沿用填滿那一筆的 alpha）。不能「只要框線不要底色」。

### B-2 改法
- 資料（`src/model/types.ts`）：
  - `CardBox.fillOn?: boolean`（預設 true；false＝不要底色，只畫框線）。`fill`、`opacity` 保留，`opacity` 只管填滿。
  - `Stroke` 加 `opacity?: number`（字塊框線用；沒有這個欄位的舊專案沿用 `box.opacity`，看起來跟以前一樣）。
- 繪圖（`textRender.ts`）：填滿 `fillOn !== false` 才畫、alpha＝`opacity`；框線 alpha＝`stroke.opacity ?? box.opacity`。
- 面板（`TextPanel.tsx` 字塊）分兩區：
  - **填滿**：開／關、顏色（`ColorPicker`）、透明度 0–100%。
  - **框線**：開／關、顏色、透明度 0–100%、粗細（現在的「外框粗細」搬過來，範圍放大到 0–40）。
  - 填滿關、框線也關 → 提示「字塊看不到了，要不要把字塊設成『無』？」（不自動改）。
- 圖形（獨立圖形、星形等）同一套。
- 驗收：單元（舊資料沒有新欄位時畫出來和以前一樣；`fillOn:false` 不畫填滿；框線 alpha 獨立）；e2e：關填滿 → 字塊中間看得到底下影片的顏色、框線還在；框線透明度 30%；粗細；截圖（填滿＋框線、只有框線、半透明填滿＋實心框線）。

## C. 裁切（取代 feedback-4 的 D）

- **位置**：從「圖層」分頁拿掉「裁切（切掉各邊的比例）」四個滑桿；在「剪輯」分頁加「裁切」按鈕（主軌、疊加的影片／照片都可以）。
- **裁切模式**（按了之後預覽進入）：
  - 預覽顯示這個物件的**完整原始畫面**，要切掉的部分變暗。
  - **像 PPT**：四條邊的中間各一條細細的**拉霸**（短橫條／短直條，視覺細、觸控區 ≥ 44px），四個角各一個 L 形角把手；直接在預覽上拖，看著畫面切。拖的時候顯示目前保留的大小（例如「保留 72% × 100%」）但不需要使用者懂比例。
  - 雙指在框內＝移動／縮放裡面的畫面（像 IG 裁切）。
  - 比例快捷：自由、原比例、1:1、9:16、4:5、16:9。
  - 「自由形狀」：用手指沿著要留下的範圍畫一圈（自動閉合、平滑），範圍外透明；「邊緣柔化」滑桿。資料 `mask: { points: [x,y][]（0–1，相對素材）, feather }`。
  - 下方「重設」「取消」「完成」。
- **關鍵：切完畫面不要跳**。現在的 `crop` 會改變素材比例，配合 `fit` 會重新縮放填滿（切左邊 → 剩下的被放大）。新增 `cropKeepingPlace(item, asset, newCrop, geo)`：回傳新的 `crop` 和調整後的 `transform`（`scale`、`x`、`y`），讓**留下來的那塊在畫面上的位置和大小完全不變**（像 PPT）。裁切模式每次拖動都用它。單元測試：切任一邊後，保留區四個角在畫面上的座標不變（容差 0.5px）。
- 畫面：矩形裁切沿用貼圖子矩形（PR #6 已做）；自由形狀用 Pixi Graphics 遮罩（同圓角遮罩），匯出共用。
- 會動的人要跟著動 → 屬於人物去背（`2026-11-12-feedback-3.md` §4），之後做。
- 驗收：單元 `cropKeepingPlace`；e2e：剪輯分頁按「裁切」→ 拖右邊拉霸往左 → `crop.r` 變大、保留區的畫面位置不變（取樣：保留區內同一點顏色不變、被切的區域露出底下）；拖角；1:1；自由形狀畫圓 → 圓外透明；取消不改；完成一次復原；圖層分頁不再有裁切滑桿；截圖。🔴 真機：拉霸好不好抓。

## G. GIPHY 貼圖會動

### G-1 現況
- 加 GIPHY 貼圖時只存了**第一格**轉成 PNG（`stickers/giphy.ts` `giphyToPng`），所以不會動（當初的第一版做法，規劃裡「會動的貼圖」還沒做）。

### G-2 改法
- 下載 GIPHY 的會動版本：`images.fixed_height.webp`（有透明、檔案小）；沒有 webp 時用 `images.fixed_height.url`（GIF）。存成素材原檔（`image/webp` 或 `image/gif`）。
- 解碼成一格一格：
  - 有 `ImageDecoder`（WebCodecs，Safari 新版、Chromium 有）→ 用它把每一格解成 `ImageBitmap`、讀每格的時間長度。
  - 沒有 → GIF 用 `gifuct-js`（MIT，純 JS）解；WebP 動圖沒有 `ImageDecoder` 時改下載 GIF 版本。
  - 解完的格子存在記憶體快取（每個素材一份，貼圖通常 ≤ 200px 高、≤ 60 格）。
- 資料：`Asset.anim?: { frames: number; duration: number }`（秒）；照片物件不用改。
- 畫面：`scene.ts` 對有 `anim` 的照片，依「物件開始後經過的時間」取第幾格（循環播放；`(t - item.start) % duration`）→ 預覽和之後的匯出都一樣、而且可以準確定格。
- 「我的貼圖」上傳 GIF／動態 WebP 時也保留會動（現在會轉成 PNG）。
- 貼圖選單的 GIPHY 縮圖也用會動的（`fixed_width_small` 的 webp/gif）。
