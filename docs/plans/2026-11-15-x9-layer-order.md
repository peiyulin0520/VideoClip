# X9 圖層可以跨類別自由排序（2026-11-15，Opus 規劃，Sonnet 實作）

## 使用者原話（2026-11-15）
> 然後我想確認如果我想要有一個影片在最下一層，接下來文字蓋在他上面，文字的上一層再放一個影像，目前的圖層是辦得到的嗎？因為我現在的圖層在播放軸中已經把各分類區分，所以文字只能在文字調整圖層順序，但如果我是要文字夾在兩個影像之間辦得到嗎？或是目前圖層頁籤可以顯示所有分類的順序，不再另行區分分類，不然我無法確定現在文字是否有夾在有效中間

## 使用者決定（2026-11-15，看過規劃後）
> 影像不區分是不是主軌，播放軸中的素材一樣分類，在各類別排序，如果要有分類夾心，可以再自行去圖層頁面調整，圖層頁籤可以跨分類調整圖層順序，但播放軸一律是按照分類，分類下再依據順序排序。

→ 定案：
- **播放軸照舊分類**（影像／貼圖／文字／音訊各一段標題），每一類裡面照圖層真實順序排（上面的蓋住下面的）。播放軸上的換順序（拖軌道圖示、選單 ▲▼）**只在同一類裡**。
- **跨類別夾心只在「圖層」分頁調**：圖層分頁一條清單看全部順序，▲▼ 可以跨類別。
- **主軌不特別**：主軌跟其他影像軌一樣，可以上下移、文字也可以排到它下面（原本規劃的「主軌永遠在最下面」拿掉）。`baseMediaTrack` 只用來決定「匯入的影片放哪一條」，跟圖層順序無關。
- 原本的選項 A（播放軸不分類）不做；下面已改成定案版本。

## 現況（為什麼辦不到）
- `Project.tracks` 陣列的順序＝圖層順序（前面＝下面）。畫面（`engine/scene.ts`）、匯出、預覽點選都**照陣列順序**畫，本身不管種類。
- 但陣列被「分區」鎖住：`ZONE = { media:0, sticker:1, text:2, audio:3 }`（`engine/timeline.ts`）
  - `normalizeZones`（`model/migrate.ts` 載入時）把軌道照種類排好
  - `insertIndexFor`：新軌道只能插在自己那一區
  - `moveTrack`／`reorderTrack`／`moveTracksBy`：碰到別種類就停
  - `moveItemToTrack`（長按拖到「＋ 新增一軌」）用 `zoneRange`
  - `Timeline.tsx`：照 `ORDER`（字卡→貼圖→影像→音訊）分四段畫，每段一個標題列（▾ 影像 2），拖軌道圖示 `dropRow` 只跟同區比；選單 ▲▼ 碰到別種類跳 toast「影像、特效、字卡不能互相穿插」
  - `LayersTab.tsx`：清單本來就是**一條**照真實順序（最上層在最上面），但 ▲▼ 碰到別種類一樣擋
  - 版型成員軌（`groupRole:'member'`，版型裡的文字／貼圖）由 `memberTrackFor` 用 `insertIndexFor` 插在文字區／貼圖區；`shiftMemberLayer` 只跟同版型、同種類換
- 結果：文字永遠在所有影像、貼圖上面，**文字不能夾在兩個影像中間**。

## 改成（規則）
1. **畫面圖層（影像、貼圖、文字）可以任意穿插**：影像軌、貼圖軌、文字軌可以排成任何順序。
2. **每一條軌道還是只放一種素材**（影像軌只放影片照片、文字軌只放文字…）——這條不變，長按拖素材到不同種類的軌道一樣不行。只是「軌道的上下順序」自由。
3. **主軌不特別**（使用者決定）：主軌可以跟其他軌一樣上下移，別的圖層也可以排到它下面（排到全螢幕影片下面會被蓋住，那是使用者自己的選擇；圖層分頁看得到）。
4. **音訊沒有畫面**：音訊軌永遠排在陣列最後、時間軸最下面一段，不參與畫面圖層順序。
5. **版型是一整塊**：`[格子軌…, 外框所在那一列, 成員軌…]` 連在一起。
   - 格子永遠在外框下面（現在就是，`normalizeGroupTracks`）。
   - **成員軌（版型裡的文字、貼圖）改成緊貼在外框那一列的正上方**，彼此可以任意穿插（版型裡的文字可以在版型裡的貼圖下面），但不會跑出這一塊。
   - 整塊一起上下移（`expandGroupTracks` 已經是整組一起動）。
6. **新加的軌道放哪裡（預設跟現在看起來一樣）**：新軌道插在「同種類最上面那條」的正上方；還沒有這種軌道 → 插在「舊分區比它低的種類」最上面那條的正上方（例：第一次加文字 → 在所有影像、貼圖上面；第一次加貼圖 → 在影像上面、文字下面）；都沒有 → 陣列最前面（最下層；版型塊不拆開）。這樣使用者不手動換順序時，結果跟現在一模一樣。

## 步驟

### X9-1 引擎規則（純函式＋單元測試，先做）
檔案：`src/engine/timeline.ts`、`src/engine/layoutTracks.ts`、`src/model/migrate.ts`、`src/store/actions.ts`
- `ZONE` 留著，但**只當「新軌道預設位置」的參考**（改名或加註解：`DEFAULT_RANK`）；新增 `isVisual(kind) = kind !== 'audio'`。
- `normalizeZones(tracks)` → 改名 `normalizeLayers`：只做一件事：音訊軌搬到最後（相對順序不變）；其他順序**原樣保留**。`migrate.ts` 兩處改呼叫它。舊專案本來就是分區排好的，結果不變。
- `insertIndexFor(tracks, kind)` 照「規則 6」重寫：
  - `audio` → 陣列最後。
  - 其他：找同種類（排除 groupRole 軌）最上面那條 → 它的 index＋1；沒有 → 找 `ZONE` 比它小的種類最上面那條 → index＋1；都沒有 → index 0。
  - 注意：不能插進版型那一塊中間（插入點落在某版型的格子軌／成員軌範圍內 → 往上移到那塊的上面）。寫一個 `blockEnd(tracks, i)` 幫手。
- 兩種「換一層」，分開寫：
  - **同類換一層** `moveTrackInKind(tracks, id, dir)`（播放軸選單 ▲▼、播放軸拖軌道圖示用）：往上＝搬到「上面最近那條同種類軌道」的正上方（中間隔著的別種類軌道被跨過去，相對順序不變）；往下同理。沒有同種類鄰居＝不動。
  - **跨類換一層** `moveTrack(tracks, id, dir)`（圖層分頁用）：拿掉 `kind !== kind` 的檢查，規則如下。
- `moveTrack`（跨類）：
  - 音訊只跟音訊換；畫面軌不能換到音訊後面。
  - 跳過整個版型那一塊：往上一層碰到版型塊 → 一次跨過整塊（`[格子…外框列…成員…]`）。
  - 自己是外框所在列 → 整塊一起動（交給 X9-1 的 `moveBlock`）。
  - 成員軌不走這裡（走 `shiftMemberLayer`）。
- `reorderTrack(tracks, id, toIndex)`：畫面軌夾在 `[0, 最後一條畫面軌]`（音訊另外夾在音訊範圍），不能落在版型塊中間（落在中間就放到那塊上面或下面，看離哪邊近）。
- 播放軸拖軌道圖示用新的 `reorderInKind(tracks, id, toKindIndex)`：`toKindIndex`＝在同種類軌道裡的第幾條（0＝最下）；做法＝把它搬到那條同種類軌道的正上方／正下方（跟 `moveTrackInKind` 同一個想法），別種類軌道的相對順序不動。
- `moveTracksBy`（播放軸多選一起移）：維持「只在同類裡」，但改成跟 `moveTrackInKind` 一樣跨過中間的別種類軌道（不再是「鄰居不同類就停」）。
- `moveItemToTrack` 的新增軌道（播放軸那一類上下的「＋ 新增一軌」）：`edge:'top'` → 同種類最上面那條的正上方（沒有就照 `insertIndexFor`）；`edge:'bottom'` → 同種類最下面那條的正下方（不能插進版型塊中間）。
- `normalizeGroupTracks`（`layoutTracks.ts`，`projectStore.apply` 每次都跑）：除了把格子軌搬到外框列正下方，**也把成員軌搬到外框列正上方**（成員軌彼此相對順序不變；同一列有多個版型外框時，照外框在時間上的先後排）。
- `memberTrackFor`（`actions.ts`）：新成員軌插在「這個版型最上面那條成員軌」正上方；還沒有成員軌 → 外框列正上方。（`normalizeGroupTracks` 也會修正，但直接插對比較好懂。）
- `shiftMemberLayer`：拿掉 `o.kind !== t.kind` 的限制 → 只要是同一個版型的成員軌都可以換（版型裡的文字可以跑到版型裡的貼圖下面）；碰到這個版型以外的軌道就停（回傳 false）。
- 版型外框所在列 ▲▼：同一條影像軌上也可能有一般片段（例如主軌）。這一列帶著它上面所有版型的整塊一起動。
- 單元測試（新檔 `src/engine/layerOrder.test.ts`，並改舊的）：
  - 陣列 `[主軌, 影像2, 文字]`：`moveTrack(文字, -1)` → `[主軌, 文字, 影像2]`（文字夾在主軌和影像2 中間）；再 `moveTrack(文字, -1)` → `[文字, 主軌, 影像2]`（主軌不特別，文字可以到它下面）。
  - 同類換一層：`[主軌, 文字, 影像2]` 時 `moveTrackInKind(主軌, 1)` → `[文字, 影像2, 主軌]`（跨過文字，搬到影像2 上面；文字跟影像2 相對順序不變）；`moveTrackInKind(文字, 1)` 不動（沒有別的文字軌）。
  - `reorderInKind`：三條影像中間夾一條文字，拖最下面的影像到同類第 2 條 → 只動影像之間的順序。
  - 音訊不會換到畫面軌中間；畫面軌不會換到音訊後面。
  - `insertIndexFor`：已有 `[主軌, 影像2, 文字]` 再加文字 → 在舊文字上面；加貼圖（還沒有貼圖）→ 在影像2 上面、文字下面；把文字移到影像2 下面後再加影像 → 插在影像2（最上面的影像）上面。
  - `normalizeLayers`：舊專案（分區排好的）原樣；音訊在中間的 → 搬到最後；畫面軌任意穿插的 → 原樣。
  - `normalizeGroupTracks`：成員軌散在別處 → 搬到外框列正上方，格子在正下方。
  - `reorderTrack` 落在版型塊中間 → 被推到塊的上面或下面。
  - 舊測試要改：`timeline.test.ts`、`timeline.free.test.ts`、`timeline.multi.test.ts` 裡「不能跨區／夾在同一區」的斷言，改成新規則（測「播放軸同類換一層跨過別類」「音訊只跟音訊」「版型塊不拆開」）。

### X9-2 播放軸：照舊分類，類別裡照真實順序；換順序只在同一類
檔案：`src/app/editor/Timeline.tsx`
- 顯示**不變**：照 `ORDER` 分四段（字卡、貼圖、影像、音訊），每段標題列與收合照舊。每一段裡的列照陣列反過來（上面蓋住下面的）——現在的寫法 `all.filter(kind)` 已經是這樣，穿插後也對，不用改。
- 主軌那一列：高度照舊（`BASE_H`，方便看縮圖）；但選單**要有** ▲▼，也可以拖（使用者：主軌不特別）。
- 拖軌道圖示 `dropRow`：維持「只跟同一類的列比」；放開時改呼叫新的 `moveTrackInKindTo(trackId, 同類第幾條)`（包 `reorderInKind`），不要再用陣列 index（穿插後同類的列在陣列裡不連續）。
- 軌道選單 ▲ 往上一層／▼ 往下一層：一般軌改呼叫 `shiftTrackInKind`（包 `moveTrackInKind`）；沒有同類鄰居才 toast「已經是這一類最上面（下面）的軌道」。**拿掉「影像、特效、字卡不能互相穿插」**，改成：「要讓文字夾在影像中間，到『圖層』分頁調整」。成員軌照舊 `shiftMemberLayer`。
- 長按拖素材的「＋ 新增一軌」放置區：顯示不變；放下時照 X9-1 的 `moveItemToTrack` 新規則。
- 多選上移／下移（`moveTracksMulti`）：照 X9-1 改過的 `moveTracksBy`。
- **夾心提示**：某一類裡的軌道跟別類有穿插時（例：有文字軌在某條影像軌下面），那一類的標題列右邊加一個小標「已穿插」（點了切到圖層分頁）。讓使用者知道播放軸的上下不等於全部的上下。小標用 `.zone-soft` 的淡底色、`--fs-note` 字。

### X9-3 圖層分頁：一條清單看全部順序，可以跨類別上下移
檔案：`src/app/editor/tabs/LayersTab.tsx`、`src/store/actions.ts`、`src/app/styles.css`
- 清單維持「這一秒的圖層，上面的蓋住下面的」，每列加：
  - 左邊**種類小標籤**（影像／貼圖／文字，三種不同底色），讓使用者確認「文字夾在兩個影像中間」。
  - 列前面的**層數**「第 3 層」（從下往上數，只數這一秒有東西的）。
  - 版型裡的東西（格子、版型成員）縮排一格，前面寫「版型 · 名稱」；外框列寫「整個版型」。
- ▲／▼ 改成「**跟這一秒的上一個／下一個圖層換位置**」，不是跟陣列裡的鄰居換（鄰居可能這一秒沒東西，按了畫面沒變化，使用者會以為壞了）。新增 action `moveTrackPast(trackId, otherTrackId)`：把 trackId 搬到 otherTrackId 的上面（往上）或下面（往下），用 X9-1 的 `reorderTrack` 規則夾住；一步復原。
  - 格子列：▲▼ 不能用（disabled），旁邊提示「格子在版型外框下面；要換格子順序請到版型分頁」——或者乾脆不顯示 ▲▼。
  - 成員列：▲▼ 在同一個版型的成員之間換（`shiftMemberLayer` 改成也是「跟這一秒的上一個／下一個成員」換）。
  - 已經最上面／最下面才 toast，**拿掉「不能互相穿插」的字**。
- 再加兩顆小鈕（放在同一列最右、跟 ▲▼ 同一個 `.btn-zone`，跟眼睛／鎖頭用 `.zone-sep` 隔開——使用者規則）：「移到最上」「移到最下」，aria-label `${track.name} 移到最上層`／`移到最下層`。320 寬不能換行：按鈕太多就把「移到最上／最下」收進一個 `⋯` 選單。

### X9-4 版型裡的圖層（跟 X9-1 一起驗）
- 成員軌緊貼外框列上方（X9-1 的 `normalizeGroupTracks`）→ **舊專案載入後**，版型裡的文字從「所有影像上面」變成「版型正上方」。只有「版型上方同一時間還有別的影像疊著」的專案畫面會變（版型裡的字會被那個影像蓋住）。可接受，寫進 PROGRESS 的「踩到的坑」。
- 播放軸版型展開後的分類子標題（文字／貼圖／影像／音效）**保留**（那是版型內的收合分組，L3 使用者要的），但子標題的順序改成照成員軌真實順序：文字和貼圖穿插時，就不分子標題，直接照順序列出成員列（子標題只剩「影像（格子）」和「音效」）。若實作太繞，第一版先保留子標題、在 PROGRESS 標成已知限制。
